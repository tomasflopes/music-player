# Refill (mix refill + solo-song extension) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mix appends its next 25 songs when 5 or fewer non-manual entries remain; a single song tapped in Search plays at once and is extended with about 5 songs that sound like it, refilled at 2 or fewer left.

**Architecture:** The engine (`:playback`) publishes a small `RefillSignal` in `PlaybackState` only when the queue has a seed. `QueueRefiller` in `:app` collects it, asks the `RefillSource` that handles the seed for a batch (mix: `MixEngine`; song: the song-radio path) on `Dispatchers.Default`, and sends `appendBatch(songs, seed, epoch, source)`; the engine drops a batch whose epoch moved.

**Tech Stack:** Kotlin, Media3 session commands, Room (unchanged), DataStore, Hilt (`@IntoSet`), JUnit. Gradle: `./gradlew check` locally on the Mac.

**Spec:** `docs/plans/2026-11-20-refill-design.md` (read it first). Context: `docs/plans/2026-11-16-mix-engine.md`, ADR 0076, 0072, 0075, 0077.

## Global Constraints
- Onion architecture: `:core:*` pure Kotlin; extension by new implementations (`RefillSource` is a Hilt set), not `when` blocks. SOLID, DRY.
- Numbers: solo batch 5, solo low-water 2; mix batch 25, `MixConfig.refillLowWater` 5. Low-water must be below batch size, validated at construction.
- Refill only when repeat is OFF. Nothing runs at app start except collecting the small signal; heavy dependencies are `dagger.Lazy`. All library reads and batch building on `Dispatchers.Default`. Do not copy `StartRadio`'s `observeSongs().first()` on the caller's dispatcher.
- Logging: tapped song stays `PlaySource.SEARCH`, picked. Appended solo songs `PlaySource.RADIO`, appended mix songs `PlaySource.MIX` with the mix id; appended songs are never `PICKED`.
- Manual entries stay before auto songs; refill counts only non-manual entries.
- ADR numbers 0078, 0079, 0080 (0081 only if the phone shows refill is slow); never edit an accepted ADR; update `docs/adr/INDEX.md`.
- **Git: commits carry no Co-Authored-By or Claude-Session lines** (owner's rule; overrides any tool default). English everywhere.
- A green `./gradlew check` is not recorded for the current tree; run it first (Task 0 of execution) and report the result, never assume it.

## Review Focus
- A batch finishes after the owner tapped another song: appended nothing (epoch guard), even when the same song is tapped again.
- Repeat ALL or ONE on a seeded queue: no refill; repeat back to OFF: refill resumes.
- Seed song with no sound profile, or removed from the library: plays alone, no message, no retry loop within the epoch.
- Mix deleted or edited mid-play: deleted does nothing; edited uses the new seeds at the next refill.
- Manual song playing with 0 auto songs ahead: the queue is still extended (seed comes from the last auto entry).
- Shuffle on, then off: appended songs are in `originalOrder` and come back in order.
- Queue restored after process death (v4) keeps extending; a saved v3 queue is dropped, not crashed on.
- Setting "Extend single songs" turned off mid-queue: no more solo refills; mix refills continue.
