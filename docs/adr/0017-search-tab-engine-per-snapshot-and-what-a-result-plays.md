# 0017: Search tab builds one immutable engine per library snapshot and decides what a result plays

Date: 2026-11-13 · Status: accepted

**Context.** ADR 0012 fixed how matching ranks; the tab still had to decide how the index follows the library and what choosing a result does. `SearchIndex` is mutable and not thread-safe, `:core:search` has no engine interface (the plan's `SearchEngine` never landed there), and there are no artist or album pages yet (plan Task 26). `SongFeatureReader` has no change signal, and the scanner rewrites featured artists after the song batches.

**Decision.** `:app` owns a `SearchEngine` seam with a `SearchEngineFactory` (Hilt-provided, so another engine can be benchmarked beside the core one, CLAUDE.md). The factory builds a new `SearchIndex` per snapshot on `Dispatchers.Default` and queries run there too; the ViewModel swaps whole engines, so a keystroke never races a rebuild. Artists, albums and songs are combined, debounced 300 ms (so the featured-artist write lands first), then rebuilt. The engine is kept while the tab's ViewModel lives. `Searcher` now sets `more*` when "See all" would show anything the section does not, mid-word matches included; before, a section with four or fewer exact or whole-word matches hid its mid-word matches for good. Choosing a result appends a `SearchEvent` and plays: a song queues the songs shown (section or "See all") from it with `PlaySource.SEARCH`, `picked = true`; an artist shuffles with `ARTIST_SHUFFLE` from a row and plays in order with `ARTIST` from the card; an album plays in order with `ALBUM`, shuffled only from the card. Artist and album plays are not `SEARCH`, so the log keeps naming the kind of list.

**Consequences.** The debounce is a heuristic, not a guarantee: a scan whose feature write lands later than 300 ms after the last library change leaves featured artists stale until the next change. A `Flow` of featured artists on `SongFeatureReader` would remove it and is the follow-up. Artist and album rows play instead of opening a page until Task 26. Not verified here: `./gradlew check` and everything on a device.
