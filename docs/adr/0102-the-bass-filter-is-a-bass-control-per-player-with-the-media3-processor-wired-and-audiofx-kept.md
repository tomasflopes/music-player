# 0102: The bass filter is a `BassControl` per player; the Media3 processor is wired and audiofx is kept

Date: 2026-11-23 · Status: proposed · Extends 0061, 0097, 0100, 0101

**Context.** The engine must set a bass gain on the outgoing and on the incoming player and put both back to no processing whenever the overlap ends early. CLAUDE.md asks that anything on the audio path sits behind an interface with the old implementation kept for benchmarks, and that a contract test runs on every implementation.

**Decision.** `BassControl` (`targetDb`, `setGainDb`, `bypass`; any thread) with `NoBassControl`, and `BassControlSource` (the engine asks it for a player's control; the default answers `NoBassControl`, so phase 6 and the tests without a filter are unchanged). Implementation 1 is `ShelfAudioProcessor`: a Media3 `BaseAudioProcessor` over `BassShelf`, 16-bit and float PCM, any other format makes it inactive. It is always active in the chain and copies the input byte for byte while flat, because a processor's active state is read only at a flush. Implementation 2 is `AudioFxBassControl` (the platform `Equalizer`, lowest band), not wired, for a later benchmark. `BassPlayers` (Hilt `@Singleton`) builds the players with the filter last in the sink chain (ADR 0101) and keeps each player's control in a weak map; the service's player and the engine's spare are built through it, and so are the lab's two. `TwoPlayerCrossfadeEngine` takes the source as its last constructor argument. It sets the spare's cut when it preloads it, drives both gains from the plan's `BassCurve` by the incoming position every 25 ms with the volumes, and calls `bypass` on both players at the end of the overlap, a skip, a jump, a seek, a queue or settings change (all `invalidate`), a pause (the swap stops for good) and `release`, and on every `discard`, in the same places as the speed reset of ADR 0097. A phase lock give-up does not stop the swap. The contract is `BassControlContract`, plain checks with no JUnit: in `src/test` for the shelf processor on the JVM, and a copy in `src/androidTest` for audiofx on a device (the two source sets could not share one file without a source-set setting that AGP 9 did not accept; the copies are kept the same by hand).

**Consequences.** Outside a transition a player's filter does no filtering, but its processor still copies each buffer. A zero-copy bypass is a named next step if the battery impression asks for it. The audiofx implementation cannot reach the same cut or smoothness and is unbenchmarked. Engine, processor and contract tests are written; none was run through Gradle (see phase 7 file). Not accepted until `check`, `deviceCheck` and the phone checks pass.
